# Beta Exit Criteria

M10 can move toward release-candidate work only when these gates are met.

## Product Evidence

- At least 3 design partner workspaces complete the core workflow.
- Each workspace validates ticket intake, AI suggestion review, knowledge publish and channel intake.
- At least one partner validates manual payment willingness or budget owner interest.

## Quality Evidence

- No unresolved critical beta bugs.
- All high-severity beta bugs have owner, workaround and milestone.
- Automated backend, web, E2E and migration checks pass.

## Operations Evidence

- Support process has been exercised with real beta feedback.
- Data reset runbook is rehearsed in test data only.
- Known issues are updated before RC planning.

## Release Boundaries

- Production release remains blocked until explicit approval.
- Legal/compliance materials remain draft-only until professional review.
- Paid resources remain blocked until explicit approval.
