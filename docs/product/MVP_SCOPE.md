# 第一阶段 MVP 范围定义

> **工作产品名：灵犀服务台 / Lingxi Service Desk**  
> **版本：V1.0**  
> **日期：2026-07-14**  
> **开发周期：8—12 周（个人工作室）**  
> **目标：完成首个端到端闭环，验证产品可用性**

---

## 1. 定义原则

MVP 不是功能清单的缩小版，而是**最小可用闭环**：用户能够从注册到完成一次有效解决的完整体验。

**核心约束**：
- 个人工作室独立完成，不外包核心逻辑
- 开发周期 8—12 周
- 满足设计伙伴验证需求
- 不追求功能完整性，追求价值可验证

---

## 2. MVP 必须包含

### 2.1 工作区与身份（P0）

| 功能 | 说明 | 验收标准 |
|---|---|---|
| 自助注册 | 邮箱注册，创建工作区 | 5秒内完成注册并进入 onboarding |
| 工作区配置 | 名称、简称、时区（默认 Asia/Shanghai） | 数据持久化，跨会话保持 |
| 邀请成员 | 邮件邀请，三种角色：请求人/坐席/管理员 | 邀请链接 72 小时有效，角色权限生效 |
| 基础 RBAC | Owner/Admin/Agent/Requester 四级权限 | 越权访问返回 403 |

### 2.2 请求入口（P0）

| 功能 | 说明 | 验收标准 |
|---|---|---|
| Web 请求门户 | 工作区子域名，自然语言输入 | 支持附件、截图，提交后显示工单编号 |
| 邮件接入 | 专属收件地址，解析邮件线程 | 回复邮件自动追加到同一工单 |
| 飞书机器人 | 私聊/@机器人提问，卡片展示状态 | 签名校验通过，消息不丢失 |

> **注意**：企业微信和钉钉推迟到 P1，避免同时开发三大 IM 导致周期失控。

### 2.3 统一收件箱（P0）

| 功能 | 说明 | 验收标准 |
|---|---|---|
| 队列视图 | 我的队列、未分派、SLA 风险、已解决 | 数据实时更新，支持筛选 |
| 快速操作 | 分派、改状态、插入知识、生成回复草稿 | 操作后即时反馈 |
| 工单详情 | 对话记录、AI 建议、关联知识、SLA 倒计时 | 信息完整展示，操作流畅 |

### 2.4 工单管理（P0）

| 功能 | 说明 | 验收标准 |
|---|---|---|
| 创建工单 | Web/邮件/IM 自动创建，保留原始消息 | 来源标识清晰，原始内容不可覆盖 |
| 状态机 | New → Triage → InProgress → Resolved → Closed | 状态流转符合业务规则 |
| 优先级 | P1-P4，AI 建议 + 人工确认 | P1 默认要求人工确认 |
| 附件 | 图片、文档上传，大小限制 | 支持常见格式，安全扫描 |

### 2.5 AI 辅助（P0）

| 功能 | 说明 | 验收标准 |
|---|---|---|
| AI 分类与摘要 | 意图识别、摘要生成、缺失信息提示 | 输出结构化 JSON，置信度可配置 |
| 优先级建议 | AI 建议 impact/urgency，人工可修改 | 建议可追溯，人工修改后记录 |
| RAG 检索 | 文档导入、向量检索、引用式回答 | 回答包含知识引用，无幻觉 |
| 回复草稿 | AI 生成回复草稿，人工可编辑后发送 | 草稿包含语气选项和知识引用 |
| 知识草稿 | 工单解决后自动生成知识草稿 | 包含问题、步骤、验证要点 |

### 2.6 知识库（P0）

| 功能 | 说明 | 验收标准 |
|---|---|---|
| 文档导入 | 支持 Markdown、TXT、PDF、DOCX | 导入后自动切片，进入向量索引 |
| 知识状态 | Draft → Review → Published | 只有 Published 内容进入 AI 索引 |
| 知识权限 | 全员可见/指定团队可见/坐席专用 | 权限过滤生效 |

### 2.7 SLA 基础（P0）

| 功能 | 说明 | 验收标准 |
|---|---|---|
| SLA 策略 | 响应时间、解决时间，按优先级匹配 | 策略可配置，首匹配生效 |
| SLA 计算 | 工作日历、暂停与恢复 | 计算结果可回放，P95 < 200ms |
| SLA 提醒 | 50%、80%、100% 阈值提醒 | 站内和邮件提醒 |

### 2.8 商业化基础（P0）

| 功能 | 说明 | 验收标准 |
|---|---|---|
| 套餐与配额 | Free/Team/Growth 三档，坐席/工单/AI 动作限额 | 额度控制生效，超限时提示 |
| 试用机制 | Growth 14 天试用，到期回落 | 不要求信用卡，到期提示 |
| 支付入口 | 对接第三方聚合支付（微信/支付宝） | 支付流程可完成，订单状态正确 |
| 用量账本 | 记录工单量、AI 动作消耗 | 数据不可篡改，可查看历史 |

### 2.9 合规与安全（P0）

| 功能 | 说明 | 验收标准 |
|---|---|---|
| 多租户隔离 | workspace_id 字段 + RLS/显式过滤 | 跨租户访问返回空或拒绝 |
| 审计日志 | 所有写操作记录 | 日志包含操作人、时间、变更内容 |
| 数据导出 | 工单、知识、配置数据导出 | 导出为 CSV/JSON，权限校验 |
| 数据删除 | 工作区删除，30 天冷静期 | 删除后数据不可访问 |
| AI 数据控制 | 默认不使用客户数据训练公共模型 | 设置项可见，开关生效 |

### 2.10 产品分析（P0）

| 功能 | 说明 | 验收标准 |
|---|---|---|
| 核心事件埋点 | 注册、连接入口、创建工单、AI 建议、解决 | 事件包含必要属性，无敏感信息 |
| 基础报表 | 工单量、解决率、SLA 达成率、AI 采纳率 | 数据准确，展示清晰 |

## 3. MVP 质量标准

| 指标 | 目标 |
|---|---|
| 注册到工作区创建 | P95 < 5 秒 |
| 工单创建 | P95 < 800ms（不含异步 AI） |
| 收件箱首屏 | P95 < 2 秒 |
| AI 首 Token | P95 < 4 秒 |
| AI 完整回复 | P95 < 15 秒 |
| 可用性 | ≥99.5% |
| AI 建议采纳率 | ≥40% |
| 无严重租户隔离问题 | 通过安全测试 |

---

## 4. 端到端闭环验证路径

```
注册工作区 → 连接入口（飞书/邮件/Web）→ 接收首个真实请求 
→ AI 分类/摘要 → 人工处理或 AI 自助回答 → 确认解决 
→ 生成知识草稿 → 查看报表
```

**验证目标**：3 家设计伙伴连续使用两周，处理至少 200 个真实请求。

## 5. 版本演进路线

| 阶段 | 时间 | 重点 |

| MVP（当前） | 8—12 周 | 完成首闭环，验证可用性 |
