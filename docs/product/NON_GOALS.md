# 第一阶段明确不包含的功能

> **工作产品名：灵犀服务台 / Lingxi Service Desk**  
> **版本：V1.0**  
> **日期：2026-07-14**  
> **适用阶段：MVP（8—12 周）**

---

## 1. 原则

本文件定义 MVP 阶段**明确不做**的功能。这些功能要么：
- 超出个人工作室 8—12 周的开发能力
- 对完成首闭环不是必需的
- 会分散核心价值验证的注意力
- 需要与外部系统深度集成，复杂度高

**任何新增功能必须经过严格的价值验证**，防止产品从"AI 服务收件箱"变成"重型 ITSM"。

---

## 2. 明确不做的功能

### 2.1 完整 ITSM 体系

| 功能 | 原因 | 计划阶段 |
|---|---|---|
| 完整 CMDB（配置管理数据库） | 建设周期长，需要自动发现和复杂关联，MVP 不依赖资产数据 | P2（PMF 后） |
| 变更管理和发布管理 | 需要变更委员会、审批链、回滚机制，复杂度高 | P2（PMF 后） |
| 问题管理和根因分析 | 需要大量历史数据和事件聚类，MVP 阶段数据不足 | P2（PMF 后） |
| 事件聚类和重大事件管理 | 需要成熟的告警集成和关联算法 | P2（PMF 后） |
| 容量和可用性管理 | 需要监控系统集成，非核心价值 | P2（PMF 后） |
| 供应商管理 | 需要合同、绩效评估等复杂流程 | P2（PMF 后） |

### 2.2 终端和基础设施管理

| 功能 | 原因 | 计划阶段 |
|---|---|---|
| 远程控制 | 需要客户端软件和安全审批，复杂度高 | 不计划 |
| 终端管理（MDM） | 需要客户端代理和设备管理能力 | 不计划 |
| 补丁管理 | 需要与补丁源集成，安全风险高 | 不计划 |
| 监控、日志、APM | 需要独立的可观测性平台 | P2（PMF 后） |
| 链路追踪 | 需要全链路埋点，非 MVP 核心 | P2（PMF 后） |

### 2.3 复杂流程自动化

| 功能 | 原因 | 计划阶段 |

### 2.5 身份与安全

### 2.8 技术能力

| 功能 | 原因 | 计划阶段 |
|---|---|---|
| 自研基础大模型 | 资源和时间投入巨大，不具备可行性 | 不计划 |

## 3. 拒绝标准

任何功能请求必须满足以下条件才能进入 MVP：

1. **与首闭环直接相关**：缺少此功能会导致用户无法完成"注册→连接入口→接收请求→解决→沉淀知识"的闭环。
2. **个人工作室可独立完成**：不需要外部依赖、第三方认证或大量集成工作。
3. **开发时间 ≤ 1 周**：单个功能开发时间不超过 5 个工作日。
4. **有明确验证指标**：可以通过设计伙伴使用数据验证价值。

**违反任一条件的功能，一律推迟到后续阶段。**
