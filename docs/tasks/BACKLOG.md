## 1. 任务划分原则

| 原则 | 说明 |
|---|---|
| 单一目标 | 每个任务只完成一个明确的功能或修复 |
| 独立可测 | 任务完成后可以独立验证 |
| 时间可控 | 单个任务开发时间 ≤ 8 小时（一个编码会话） |
| 依赖清晰 | 明确列出前置依赖 |
| 验收标准 | 每个任务有明确的验收条件 |

## 11. 首个端到端闭环任务

**推荐首个闭环路径**：

```
注册工作区 → 连接邮件入口 → 发送邮件创建工单 → AI 分类摘要 → 人工处理并解决 → 确认解决
```

**对应的开发任务顺序**：

1. S0-01：项目初始化
2. S0-02：数据库环境搭建
3. S1-01：用户注册 API
4. S1-02：工作区创建 API
5. S1-03：登录认证 API
6. S2-01：工单数据模型
7. S2-02：工单状态机
8. S2-05：邮件接入 API
9. S3-01：AI Gateway 封装
10. S3-02：AI 分类服务
11. S3-03：AI 摘要服务
12. S2-07：统一收件箱 API
13. S5-08：工单解决确认

**闭环验证标准**：
- 用户通过邮箱注册并创建工作区
- 配置工作区专属邮件地址
- 发送测试邮件，自动创建工单
- AI 自动生成分类和摘要
- 坐席在收件箱看到工单并处理
- 标记工单为已解决
- 用户收到解决确认通知
